# Review: host-aware setup design

The direction is plausible, but the spec is not implementation-ready. Codex-host scope remains undecided, and the proposed state/write contracts cannot provide the stated failure isolation or safely handle malformed managed blocks.

## Blockers

1. **Codex-host support is deferred, not resolved.** The source requirement makes Codex a minimum supported host (`requirements/requirements-codex.md:9`) and identifies only its contracts as unverified (`requirements/requirements-codex.md:73`), while the analysis cuts it pending an open question (`analysis.md:34,44`) and the spec both models only two hosts (`design.md:7-10,94`) and calls Codex unresolved (`design.md:188`). Lack of research supports delaying design, not silently narrowing the stated personal-machine goal; ADR-1 even incorrectly says there are “three hosts today” (`design.md:126`). **Suggested fix:** verify current Codex contracts and include it, or obtain and record an explicit scope decision that supersedes R1 before approval.

2. **Cross-host failure isolation is impossible with the specified writer.** `apply` receives one flat `list[Change]` and writes sequentially (`design.md:62,71,89`), matching current `apply` (`skill/tools/setup_models.py:193-206`); if a later host fails, earlier files are already changed, contradicting “does not touch another host” and NFR-07 (`design.md:89,173`). **Suggested fix:** define per-host plans plus a complete preflight/rollback or weaken the invariant to “a failure does not corrupt unattempted hosts.”

3. **Malformed blocks have contradictory and unsafe semantics.** `stored_choices` says no closed block means unconfigured (`design.md:87`), ADR-2 says an unmatched pair is reported and not repaired (`design.md:137`), but NFR-02 lists unmatched-marker merge tests (`design.md:168`); current `block_span` returns `None` and `merge_block` appends a second block (`skill/tools/setup_models.py:102-106,131-138`). **Suggested fix:** specify malformed markers as a validation error that prevents every write in that host plan, with an exact test and diagnostic.

## Should-fix

4. **ADR-4 does not adequately dispose of automated host verification.** Codex R11 requires a local smoke test beyond fixtures (`requirements/requirements-codex.md:29`), but ADR-4 equates automation with setup always driving signed-in hosts and replaces proof with agent self-report and a manual hook check (`design.md:147-153`). An optional on-host verifier can skip cleanly when unavailable without breaking bare-machine `-y`. **Suggested fix:** provide an opt-in smoke-test command/fixture harness per installed surface, or explicitly accept that discoverability and enforcement remain unverified and stop claiming equivalent configured outcomes.

5. **ADR-2 is not wired into executable `-y` behavior.** The analysis requires `-y` to keep recorded hosts, otherwise use detected hosts, otherwise Claude (`analysis.md:12,36-37`), but the spec gives only prose in `main` (`design.md:53,65,135`) and no contract for deriving the selected host tuple before per-host `stored_choices`; current `main` has one fixed Claude folder and one stored choice (`skill/tools/setup_models.py:81-93`). **Suggested fix:** specify and test a pure `selected_hosts(yes, configured, detected)` transition for all configured/detected/fallback combinations before planning writes.

6. **Host-specific defaults cannot be implemented through the stated `stored_choices` contract.** Missing lines take “its default” (`design.md:87`), yet the function receives only file text, and current parsing fills from one global `DEFAULTS` (`skill/tools/setup_models.py:115-128`); `ask_choices` likewise needs provider suggestions indexed in `SUGGESTED` (`skill/tools/setup_models.py:148-155`), while Copilot has no suggestions (`design.md:99`). **Suggested fix:** pass a host-owned `ModelChoices` default and suggestion policy into parsing/prompting, and define how a provider with no suggestions chooses a changed-provider default.

7. **The state diagram loses existing configuration on a declined edit.** A recorded host can move to `Planned` after changed answers (`design.md:38`), but declining then goes to `Unconfigured` (`design.md:40-42`) even though no write occurred and its old block remains. **Suggested fix:** split planned-new from planned-update, or return a declined update to `Recorded`.

8. **Several draft requirements disappear without an analysis decision.** Atomic writes and repair of partial state (`requirements/requirements-claude-sonnet-5-5.md:49-51`), parse-before-write failure (`requirements/requirements-claude-sonnet-5-5.md:52-53`), no outbound personal data (`requirements/requirements-claude-sonnet-5-5.md:45-46`), absent-host reporting (`requirements/requirements-claude-sonnet-5-5.md:38-39`), and spaces/non-ASCII paths (`requirements/requirements-codex.md:42`) are neither carried nor explicitly cut at `analysis.md:29-44`; NFR-06 covers written block text only (`design.md:172`). **Suggested fix:** add these as contracts/NFRs with tests, or add explicit analysis resolutions explaining each rejection.

9. **The “never overwrite” rules are ambiguous across a new host and existing settings.** `pending_changes` replaces a settings model only on an interactive coordinator change (`design.md:88`), but for a newly selected Claude host there is no stored block to compare even if `settings.json` already has a user model; current `overwrite` is therefore false (`skill/tools/setup_models.py:90-93`) and prints a hand-edit instruction (`skill/tools/setup_models.py:188-189`), contrary to the no-hand-edit goal in Sonnet (`requirements/requirements-claude-sonnet-5-5.md:10-12`). **Suggested fix:** state that pre-existing unowned settings are preserved and make the summary the accepted outcome, or define a separately confirmed takeover flow.

10. **The host adapter row is too small for the behavior attributed to it.** `Host` has only name, instruction file, optional settings key, and label (`design.md:46`), yet detection paths, environment-variable resolution, defaults/suggestions, installed status, surface summaries, and gate-status text differ (`design.md:53-59,96-103`); “adding a host adds one row” is therefore not testable (`design.md:79,127-129`). **Suggested fix:** enumerate all row fields and pure callbacks needed by the contracts, or drop the one-row extensibility claim.

11. **Official host facts are not traceable from the spec.** The Copilot path, shared-harness claim, `--model`, hook reading, event mapping, and enterprise-policy statements (`design.md:96-103,142,158-159,178-189`) cite only `analysis.md`, whose verified-facts section has no URLs or retrieval dates per fact (`analysis.md:20-27`). This drops Codex NFR7’s dated-source traceability (`requirements/requirements-codex.md:45`). **Suggested fix:** add direct dated official-reference links beside every relied-on fact and label inference separately.

12. **Atomicity and multi-file consistency are missing risks.** Current writes are independent `write_text` calls (`skill/tools/setup_models.py:204-206`); interruption can leave a new block without its settings model, and multi-host runs enlarge that window, but the risk section is absent and Sonnet N4 was dropped (`requirements/requirements-claude-sonnet-5-5.md:49-51`). **Suggested fix:** add interruption/partial-write risk with temp-file-and-replace semantics and a rerun repair test.

13. **Existing Copilot hook exposure is not represented as a design risk.** Opus notes that Copilot may already read repo `.claude/settings.json`, causing Claude hooks to block or fail open under a different contract (`requirements/requirements-claude-opus-5-5.md:87-90`); the spec leaves it only as an open question (`design.md:189`) while saying the Stop gate is simply Claude-only (`design.md:100`). **Suggested fix:** promote this to a risk and require the summary to say existing hooks are unverified under Copilot until portability work resolves it.

## Nits

14. **The spec over-builds for hypothetical hosts.** ADR-1 optimizes for “more likely” hosts and promises table-only extension (`design.md:126-129`) although only Claude and Copilot are in decided scope and their behavior already differs substantially. **Suggested fix:** design the two approved hosts cleanly now and retain a small data table only where it removes real duplication.

15. **The README change has no traced requirement.** The directory tree adds a README line (`design.md:117`) without identifying content or a requirement it satisfies. **Suggested fix:** remove it from scope or name the exact user-facing requirement and text it documents.
